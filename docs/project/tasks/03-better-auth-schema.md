# 03 — Better Auth schema, migration, and route

Status: not started. Depends on task 02.

## Goal

Auth tables generated by the Better Auth CLI, applied with a reviewed Drizzle migration, and a working auth route. No pages yet. Public sign-up is disabled.

- `docs/project/STATE.md`
- `docs/project/plans/foundation.md` (Better Auth, Approved dependencies, Risks)
- `.cursor/rules/nextjs-react-tailwind-ts.mdc` (Security, Better Auth)

The live docs and the 1.6.23 Context7 tag disagree. Follow the installed 1.7 types and the current docs: import `drizzleAdapter` from `@better-auth/drizzle-adapter`, not from `better-auth/adapters/drizzle`.

## Acceptance

- Auth tables exist and were created by the committed SQL migration, not by `drizzle-kit push` and not by `auth migrate`.
- `nahala_app` can `SELECT` from those tables and still cannot `CREATE TABLE`.
- `POST /api/auth/sign-up/email` is rejected while the Next.js server is running.
- `npm run typecheck`, `npm run lint`, and `npm run build` pass.
- The migration reviewer has reviewed the SQL before `db:migrate`. The security reviewer has reviewed the auth config and route after the change.

## Scope

Install:

- `better-auth@1.7.14`
- `@better-auth/drizzle-adapter@1.7.14`
- `auth@1.7.14` as a devDependency (the CLI). Do not add `@better-auth/cli` (that package is 1.4.21).

Create:

- `lib/auth.ts` with `import "server-only"`
- `db/schema/auth.ts` by CLI generation only
- Re-export it from `db/schema/index.ts`
- `app/api/auth/[...all]/route.ts`
- The Drizzle migration under `db/migrations/`

## Constraints

- `emailAndPassword.enabled: true`. No OAuth, no email verification, no `sendResetPassword`, no admin plugin, no username plugin.
- `disableSignUp` is true for the Next.js process, including development. Production forces it even if some bootstrap flag is present. The flag itself is implemented in task 06. This task only needs sign-up off.
- Minimum password length 12.
- `nextCookies()` from `better-auth/next-js` is the last plugin.
- `BETTER_AUTH_SECRET` and `BETTER_AUTH_URL` come from `lib/env.ts`. `trustedOrigins` is only the origin of `BETTER_AUTH_URL`. No wildcards.
- Generate, do not hand-write:

  ```bash
  npx auth generate --adapter drizzle --dialect postgresql --output db/schema/auth.ts --yes
  ```

  Use the local `auth@1.7.14` binary, not a floating `auth@latest`. The CLI looks for `lib/auth.ts`. If the flags differ in 1.7.14, follow `auth generate --help` and report the command you actually ran.

- Match the adapter to the relations style the CLI emits. Default adapter is relations v1 (`relations()`). Relations v2 is `@better-auth/drizzle-adapter/relations-v2` and `defineRelations`. Do not convert the generated file by hand. If it includes relations, set `advanced.database.joins: true` and pass those relations through the adapter schema. If it does not, leave joins off.
- Keep the CLI's id and timestamp types. Do not rewrite them to `timestamptz` or uuid. Report what the SQL uses.
- Then `npm run db:generate`, read the SQL, send it to the migration reviewer, then `npm run db:migrate`. Do not run `auth migrate` (Kysely path) or `auth create-admin`.
- Route exports `GET`, `POST`, `PUT`, `PATCH`, and `DELETE` from `toNextJsHandler(auth)`.
- Do not call `getSession` from the root layout.
- Cookie attribute names: the security docs say `httpOnly` is on, `sameSite` defaults to `lax`, and `secure` follows an `https` base URL. Do not force `secure` on local `http`. Set them explicitly only if the installed options document a field. Do not invent one. Task 05 checks the header.

## Security and performance

- The route is public by nature. Sign-up must still be disabled. Rate-limit tightening is task 05; do not weaken any default limiter this task inherits.
- Joins on `getSession` are allowed only when the generated relations support them. One pool, still `max: 10`.
- `lib/auth.ts` is server-only. The route handler is the only HTTP entry.

## Do not touch

Sign-in page, seed script, CSP, domain tables, roles.

## Report when done

Files changed, the exact generate command, whether relations are v1 or v2, the timestamp and id column types in the SQL, reviewer results, the sign-up rejection status code, and typecheck, lint, and build output. Do not start task 04.
