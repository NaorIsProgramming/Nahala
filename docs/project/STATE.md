## What this app is

Nahala (Hebrew: נחלה) is a Hebrew-language management application for an agricultural packing facility. It handles pallets of fruit through two different sorting and packaging steps, including the creation of pallets and dedicated sorting stages. It produces reports and statistics on command. It also exposes an API that can perform every action available through the GUI.

## Architecture map

What exists now:

- `app/layout.tsx`, `app/page.tsx`, `app/globals.css` : root shell and placeholder home page
- `app/brand.css` : Tailwind v4 theme tokens (light and dark)
- `app/icon.svg` : favicon
- `public/brand/` : `logo-mark.svg` and `logo-mark-dark.svg`
- `components/brand/logo.tsx` : logo, switched with CSS for dark mode
- `components/theme-toggle.tsx` : light / dark / system toggle
- `lib/utils.ts` : `cn()` helper
- `lib/env.ts` : server-only Zod check of `DATABASE_URL`, `BETTER_AUTH_SECRET`, and `BETTER_AUTH_URL`. No database connection.
- `db/index.ts` : the single postgres.js client (`max: 10`) and Drizzle instance. Server-only. Uses `DATABASE_URL`.
- `db/schema/auth.ts` : Better Auth tables (`user`, `session`, `account`, `verification`) and v1 `relations()`, generated by the CLI
- `db/schema/index.ts` : re-exports `./auth`. No domain tables.
- `db/migrations/0000_auth.sql` : the applied auth migration. Ids are `text`. Timestamps are `timestamp` without time zone.
- `lib/auth.ts` : server-only Better Auth instance. Public sign-up disabled unless this process sets `BOOTSTRAP_SIGN_UP=1` outside production. `nextCookies()` is the only plugin.
- `lib/auth-client.ts` : browser Better Auth client. Same-origin `/api/auth`. No server imports.
- `lib/session.ts` : server-only `getSession`, wrapped in React `cache()`
- `app/sign-in/page.tsx`, `app/sign-in/sign-in-form.tsx` : Hebrew sign-in. An existing session redirects to `/app`.
- `app/app/page.tsx`, `app/app/sign-out-button.tsx` : protected placeholder. No session redirects to `/sign-in`.
- `app/api/auth/[...all]/route.ts` : `GET`, `POST`, `PUT`, `PATCH`, `DELETE` from `toNextJsHandler`
- `next.config.ts` : static security headers for all routes. HSTS and `upgrade-insecure-requests` only when `NODE_ENV` is production. No nonce, no `proxy.ts`.
- `drizzle.config.ts` : Kit config. Uses `MIGRATE_DATABASE_URL`. Does not import `db/index.ts`.
- `db/seed.ts`, `db/register-seed.mjs` : local bootstrap user. `npm run db:seed`. The loader transpiles TypeScript because this Node build cannot strip types.
- `instrumentation.ts`, `instrumentation-node.ts` : call that check when the Node server starts
- `docker-compose.yml`, `docker/postgres/init-roles.sh` : dev Postgres only
- `docs/project/` : this file, plans, and task briefs

Planned, not created yet:

- `components/ui/` : generic reusable primitives
- `features/<name>/` : feature-specific components
- `db/schema/` : domain table files, re-exported from `db/schema/index.ts`
- `lib/services/` : one plain function file per domain area

## Key decisions

- 2026-10-26 Fully self-hosted, no third-party backend services, because the owner wants to control all data and infrastructure.
- 2026-10-26 Better Auth over Auth.js/Clerk/Supabase Auth, because it runs inside the app, stores data in our own database, and Auth.js is in maintenance mode.
- 2026-10-26 PostgreSQL + Drizzle over Prisma, because the schema is plain TypeScript and it pairs well with Better Auth's Drizzle adapter.
- 2026-10-26 PostgreSQL is never exposed to the internet. Only the app server has public ports.
- 2026-10-26 Library docs are pulled from Context7 instead of relying on model memory.
- 2026-10-26 Scaffold uses Tailwind v4 (CSS-first tokens in `app/brand.css`) and `next-themes` with `attribute="class"`, because dark mode is a `.dark` class on `<html>`.
- 2026-10-26 `next.config.ts` sets `agentRules: false`, so `next dev` does not generate `AGENTS.md`.
- 2026-10-27 Dev Postgres is `postgres:18`, volume mounted at `/var/lib/postgresql` (`PGDATA` is `/var/lib/postgresql/18/docker`). Dev compose publishes `127.0.0.1:5432:5432` only. Production compose publishes no database port and pins an exact image version.
- 2026-10-27 Public sign-up stays off. The local bootstrap user is created only by a seed that calls Better Auth's API. No roles in this work. How the first production user is created belongs in the deployment plan.
- 2026-10-27 Static CSP, with `'unsafe-inline'` only on scripts and styles, so `next-themes` keeps working. A nonce CSP is reconsidered in the foundation audit and is not adopted without a new approval.
- 2026-10-27 Role passwords are hex, so the database URLs need no encoding. The app role also gets `USAGE` and `SELECT` on sequences the migrator creates, so a later insert into an identity column can work. It still cannot `CREATE`.
- 2026-10-27 Env validation runs from instrumentation `register()` on Node only and exits the process on failure, so Next does not render the error as a page. `next build` does not call `register()`.
- 2026-10-27 The app client calls `drizzle({ client, schema })` from `drizzle-orm/postgres-js`. That form is accepted by the 0.45.4 types and is not marked deprecated. There is no `db:push` script. `drizzle-kit migrate` opens its own connection.
- 2026-10-27 Auth tables stay as the CLI emitted them: relations v1, `text` ids, `timestamp` without time zone. `account.updated_at` and `session.updated_at` are `NOT NULL` with no SQL default; Better Auth sets those values on write.
- 2026-10-27 `auth generate` cannot load `import "server-only"`. Remove it from `lib/auth.ts`, `db/index.ts`, and `lib/env.ts` only for that command, then restore it. `NODE_OPTIONS=--conditions=react-server` does not help; the CLI uses jiti.
- 2026-10-27 Production HSTS is `max-age=63072000; includeSubDomains` with no `preload`. Cookie flags stay at Better Auth's defaults: `useSecureCookies` is unset, so `Secure` follows an `https` base URL and local `http` stays unset.
- 2026-10-27 `signUpEmail` honors `disableSignUp`, so the seed sets `BOOTSTRAP_SIGN_UP=1` only in its own process, after it refuses production and a non-local database. Production keeps sign-up disabled even if that flag is set. The host check follows the hosts postgres.js dials, including a comma-separated host and a `#` fragment.

## Conventions not obvious from the code

- Database code is server-only. Never import `db` into client components.
- Schemas for user-submitted data omit or allowlist server-controlled fields (id, timestamps, userId, role).
- Security audit procedure lives in `.cursor/rules/security-audit.mdc` (invoke with `@security-audit`).
- The UI is Hebrew and RTL (`lang="he" dir="rtl"`), with light and dark themes. All UI follows `.cursor/rules/brand-design.mdc`, the tokens in `app/brand.css`, and the logo files in `public/brand/`. User-facing text is Hebrew; code, identifiers and API field names are English.
- Every action available in the GUI (creating pallets and sorting stages, reports, etc.) must also be available through the API (`/api/v1`). Business logic lives once, in plain functions in `lib/services/` (one file per domain area); the UI and API entry points are thin wrappers. Details are in the "Services and API parity" section of `.cursor/rules/nextjs-react-tailwind-ts.mdc`.

## Known issues and risks

- The owner has not set up backups or the production server.
- The shipped CSP allows `'unsafe-inline'` on scripts and styles so the `next-themes` script can run. A nonce policy is a later decision; it would force dynamic rendering.
- The auth rate limit trusts a single client-supplied `X-Forwarded-For` until `advanced.ipAddress.trustedProxies` names the real reverse proxy. That belongs in the deployment plan. There is no proxy address to set yet.
- This machine’s Node v22.22.1 reports `process.features.typescript` false, so `node --experimental-strip-types` throws `ERR_NO_TYPESCRIPT`. The seed uses `db/register-seed.mjs` and the installed TypeScript compiler instead.
